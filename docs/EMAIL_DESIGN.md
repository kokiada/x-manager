# メールアドレス台帳と受信チェックの設計

## いま実装済み（このフェーズ）

- **メールアドレス台帳**（`EmailAddress`）：アドレス、ラベル/メモ、プロバイダ
  （gmail / outlook / yahoo / other）、作成・更新日時。DB v5 の
  `emailAddresses` テーブル（`id, address, provider`）に保存され、暗号化
  バックアップの対象にも含まれる。
- **アカウントとの紐づけ**：`Account.emailId`（nullable）。アカウント追加・
  編集フォームで台帳から選べる。一覧・詳細画面で紐づいたメアドを表示する。
- **紐づけチェック**（`src/lib/emailLinkCheck.ts`、純粋関数）：
  1. メアド未設定のアカウント
  2. 同じメアドを複数アカウントで使い回しているケース
  3. どのアカウントにも使われていないメアド
- **削除時の扱い**：メアドを削除すると、それに紐づくアカウントの
  `emailId` が外れる（null になる）。アカウント自体は消えない。

## 受信メールチェックの設計（未実装・この先のフェーズ）

目的：Xアカウントの登録に使っているメールアドレスの受信トレイを確認し、
Xからの通知（ロック警告・凍結通知・認証コード等）の見落としを防ぐ。

### 優先対応：Gmail / Outlook

ユーザーの要望により、**Gmail と Outlook を優先対応**とする。
プロバイダの選択肢も gmail / outlook を先頭に並べている。
Yahoo!メールとその他プロバイダは、IMAP 設定を手入力できる形で後から対応する。

| プロバイダ | IMAP サーバー（プリセット） | 認証 |
| --- | --- | --- |
| Gmail | `imap.gmail.com:993`（SSL） | アプリパスワード |
| Outlook | `outlook.office365.com:993`（SSL） | アプリパスワード。不可のアカウントは OAuth2 |
| Yahoo!メール | `imap.mail.yahoo.com:993`（SSL） | アプリパスワード |
| その他 | 手入力（ホスト・ポート） | IMAP の認証情報 |

プリセットは `EMAIL_IMAP_PRESETS`（`src/db/types.ts`）にあり、台帳の
provider 種別と連動する。`other` の場合はプリセットなし（手入力）。

### 認証の注意点

- **Gmail**：通常のパスワードでは IMAP ログインできない。Google アカウントで
  2段階認証を有効にし、**アプリパスワード**を発行して使う。
- **Outlook**：Microsoft アカウントでも、基本認証が無効な場合はアプリ
  パスワードが必要。アプリパスワードが発行できないアカウント（組織管理下
  など）は **OAuth2**（Microsoft identity platform）での認可が必要になる。
  その場合は Electron 側で認可コードフローを実装する。
- 資格情報（アプリパスワード / OAuth2 のリフレッシュトークン）は
  **Electron の `safeStorage` で暗号化してローカルに保存**する。平文で
  IndexedDB やファイルに置かない。

### なぜ Electron 限定か

- ブラウザ版（Web アプリ）からは、ブラウザのセキュリティモデル上、
  IMAP（生の TCP/TLS ソケット）に直接つなげない。WebSocket 経由の
  中継サーバーが必要になるが、それは資格情報を外部に預けることになり、
  XBoard の「データは端末内だけ」という方針と合わない。
- Electron のメインプロセス（Node.js）なら `imapflow` 等の IMAP
  クライアントをそのまま使える。資格情報も `safeStorage` で OS の
  資格情報ストアに預けられる。したがって受信チェックは **Electron 版
  限定の機能**とし、ブラウザ版では台帳の管理だけを行う。

### MVP の範囲

1. 受信トレイの**新着ヘッダ一覧**（差出人・件名・日時）を取得する。
2. **未読数**を取得する。
3. 取得結果を台帳画面（または通知/DM集約画面）に表示する。

送信・既読化・フォルダ移動は MVP の外。X からの通知メールを見落とさない
ことだけを最初のゴールとする。

### 実装の進め方（次フェーズ以降）

1. `imapflow` を Electron の依存関係に追加し、メインプロセスに
   IMAP クライアントを実装する（接続・認証・ヘッダ取得・切断）。
2. 資格情報の保存・読み込みを `safeStorage` で実装する（暗号化）。
3. レンダラー（Web アプリ）とメインプロセスの IPC で「受信チェック実行」
   をつなぐ（`electron/preload.cjs` 経由）。
4. Gmail / Outlook のプリセット接続を、サブアカウントで試運転する。
5. OAuth2 が必要な Outlook アカウントは、認可フローを別途実装する。
